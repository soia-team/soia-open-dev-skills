# 横向重构：纵向切片的例外

本文件是 `soia-dev-draft-feature-spec` 的拆分参考：**当一次机械改动的爆炸半径横跨整个代码库、没有任何纵向切片能单独保持绿时，按 expand–contract 三段出票并写清阻塞边**。SKILL.md「按需拆分」中「不要仅按『先全后端、再全前端』分层」一条按本文件展开它的例外情形：默认仍是纵向切片，本文件记录该默认值需要让位的形状与启用证据。

起草切片不代表已经建立或授权 Goal/Task；本文件只产出切片序列与阻塞边草稿，由目标项目既有准入流程承接。验收标准写法见 `soia-dev-draft-feature-spec/references/acceptance-authoring.md`。

## 什么是横向重构

**横向重构（wide refactor）** 是一次机械改动（改列名、改共享符号类型、改一个被全库引用的命名），而它的**爆炸半径（blast radius）**横跨整个代码库：单次编辑同时打破成千个调用点，没有纵向切片能单独保持绿。

| 要素 | 判据 |
|---|---|
| 机械改动 | 改动本身不引入新行为，语义等价，可以逐点核对 |
| 爆炸半径 | 调用点分散在全库多个 package / 目录，一次编辑同时打破它们 |
| 绿不成立 | 任一纵向切片落地时都必然带着一批红调用点 |

三条同时成立才走本文件的序列；只有一条成立时回到默认的纵向切片。

## 为什么它是纵向切片的例外

默认拆分规则要求每个切片独立可验证：一条 tracer bullet 窄而完整地切过全部层，落地即可演示或验证。横向重构满足不了这条——新形态一旦落到旧调用点上，红的不是某个切片，而是全库。把这种改动硬塞进 tracer bullet 只会得到两种结果：切片在红状态下交付，或把一个不可分割的改动切成互相阻塞的假切片。

例外靠证据启用，不靠偏好：**能写出「为什么单次编辑无法保持绿」才启用本文件**。写不出这条证据时，按默认纵向切片处理。

## expand–contract 三段

| 段 | 动作 | 完成判据 | 阻塞边 |
|---|---|---|---|
| ① Expand | 把新形态加在旧形态旁边，旧形态原样保留 | 新形态可用，全库仍绿，没有任何调用点被改 | 无，可立即开始 |
| ② Migrate | 按爆炸半径分批迁移调用点（按 package、按目录），每批一张票 | 该批调用点全部走新形态，批结束时 CI 绿 | 被 ① Expand 阻塞；旧形态仍在，所以批与批之间保持绿 |
| ③ Contract | 确认没有调用者后删掉旧形态 | 旧形态从代码与文档中退役，退役证据齐备 | 被所有 Migrate 批阻塞 |

顺序固定为 Expand → Migrate → Contract。合并 ①② 或 ②③ 会重新制造「单次编辑打破全库」的状态，等于放弃本例外。

## 阻塞链：Blocked by 与集成分支

每张票写清 `Blocked by` 边：Migrate 批指向 Expand，Contract 指向每一张 Migrate 批，无前置的票写「无，可立即开始」。阻塞边是这批票的主要产物；阻塞项全部完成的票构成 frontier，可以被逐个领取。

集成分支是最后手段：只有当批与批之间也无法单独保持绿时，才让它们共用一个集成分支，并让全部批阻塞一张最终的「集成并验证」票；**绿色只在那张票承诺**。批能各自保持绿时按常规主干流程走，不引入长期分支。

## 起草要求

1. **每张票写两件东西**：它交付的端到端行为（从使用者视角描述新形态带来的结果）与阻塞边。
2. **票里写范围、集成接缝、回退与退役证据**：每批覆盖哪些 package / 目录、接缝在哪、出问题时怎么退回旧形态、Contract 依据什么判定「没有调用者」。
3. **票里用模块、package、符号名定位**：具体文件路径与行号随迁移推进即失效，让票在整个迁移期间保持可读。
4. **写明例外证据**：横向重构的票要写出为什么单次编辑无法保持绿——这是走例外的证据，不是偏好。
5. **规格里显式声明**：本次拆分是一次横向重构序列，列出三段与阻塞链，让下游知道绿在哪个节点承诺。

## 与默认值的关系

默认纵向切片；本例外只在爆炸半径证据成立时启用，并在规格里显式声明这是一次横向重构序列。当改动重新可以被某个切片独立验证时，回到默认规则。规格的完成态仍按 `soia-dev-draft-feature-spec/references/acceptance-authoring.md` 的 Closed / Open 之一交付。

## 交付前自检

1. 三要素齐备：机械改动、爆炸半径、无纵向切片可单独保持绿，逐条有证据。
2. 三段齐备且顺序为 Expand → Migrate → Contract，没有任何一步要求单次编辑同时改新旧两种形态。
3. 每张票都写了交付的端到端行为与 `Blocked by` 边，顶层票无前置、可立即开始。
4. 集成分支只在批与批之间也无法保持绿时出现，且绿色只在「集成并验证」票承诺。
5. 票内用模块、package、符号名定位；范围、接缝、回退与退役证据已显式写出。
6. 规格已显式声明这是一次横向重构序列。
