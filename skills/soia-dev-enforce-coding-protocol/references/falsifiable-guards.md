# 可证伪守卫：敏感性取证、台账与例外基线

本文件是 `soia-dev-enforce-coding-protocol` 的守卫参考：**守卫的价值来自它能失败**。设计、清点或复审守卫时加载；SKILL.md「先找证伪办法」按本文件展开到守卫的持续可证伪性——门禁脚本、检查器、审查规则、断言与基线条目都算守卫。

分工：本次新增或改动检查的**首次**取证在 `soia-dev-implement-task/references/acceptance-line.md` 的负控一节；本文件管这些守卫此后长期的敏感性与新鲜度——是否还接在被检对象上、多久没被验证过、例外有没有在悄悄堆积。

## 起点：从未失败过的守卫与有效守卫同形

一个从未失败过的守卫，与一个有效守卫在输出上都表现为一行绿。**守卫的价值来自它能失败**，因此「守卫通过」这句话本身不携带信息，除非同时能说明它有能力不通过。

按这个口径清点：门禁脚本、检查器、审查规则、断言与基线条目都算守卫，都要能被问到同一个问题——**它上一次转红是什么时候，因为什么？**

## pass → fail → pass 三步取证

一次完整的守卫取证分三步，逐步留证：

1. **确认控制前为 pass。** 记录命令与真实输出，确认守卫在动手之前就是绿的。这既是起点，也是第三步要还原回去的目标状态。
2. **植入违例，确认转红。** 植入一个已知的或范围受控的违例，确认守卫转红，且给出的失败正是预期的失败（失败位置、判定理由对得上），而不是碰巧的另一种红。
3. **精确还原，确认回到 pass。** 把状态精确还原到控制前，**包含所有既有的他人改动**；确认守卫回到 pass。

守卫若在第二步没有失败，说明它没接对被检对象——**先修守卫，再谈通过**。第三步还原不干净时，前面的通过也失去效力，因此还原的核对与植入的核对同等重要。

取证留成一条可复核的记录，三步各占一行：

```text
G1  <守卫名 / 命令>            控制前：pass，输出 <摘要>
G1  植入 <范围受控的违例>       期望失败：<判定理由>；实际：<转红输出摘要>
G1  还原 <还原动作>            复检：pass；工作树与他人的既有改动保持原样
```

## 范围不可逃

守卫要覆盖它声称覆盖的那片范围，判定才算数。把代码移出守卫作用域、跳过检查、放松断言、扩大分析范围这四类动作，无论贴什么标签（临时、兼容、已知问题、后续处理），都按抑制处理。

正当路径有两条：修根因，或者按抑制程序登记——写清来源与为何在本次授权内无法修正、owner 与移除条件、残余风险或覆盖缺口。需要护栏时的取舍：**「让守卫变绿」与「让守卫保持能失败」冲突时，取后者**；绿色不是通行证，能失败才是。

## 守卫台账

每条守卫登记一行，作为它的长期健康档案：

| 字段 | 内容 |
|---|---|
| owner | 谁负责这条守卫的判定与修复 |
| 新鲜度触发条件 | 多久没被负控验证过就要重验，按改动频率与风险定 |
| 最近一次负控检出时间 | 最近一次「安全植入违例后转红」的时间，附证据引用 |
| 真实违例 | 上线后真实触发的记录，与负控分开记 |

真实违例是边界的压力证据，用来判断守卫是否守在对的位置；**长期安静本身不构成退役一个可证伪守卫的理由**——沉默是弱证据。退役要等到更简单的义务能保住同一不变式，或有证据表明该失效机制已不再影响决策。

## 例外基线默认只缩不涨

例外基线（跳过的检查、豁免清单、允许的越界条目）默认只缩不涨。上涨是一次**可见的边界决策**，登记决策权威、理由、窄范围、owner、复核触发条件与移除条件；未经复核的增长就是例外堆积，不构成治理。

## 审查型守卫

审查规则这类以人为主体的守卫，同样要有相称的可证伪执行：写清**审查事件**（什么改动触发哪一次审查）、**保留证据**（结论落在哪、引用了什么）与**升级路径**（未通过时找谁）。纸面规则配上一次可执行、可留证的审查事件，才算接上了线；只有条文而没有事件的规则，与从未失败过的守卫同形。

## 成本过高时的诚实边界

没有安全负控手段时（例如违例只能在生产数据上植入，或植入动作本身不可逆），报告为「**green without proved sensitivity**」，并写明缺的是哪一种负控：观察修复前失败 / 临时回退或改坏行为 / 植入范围受控的违规 / 已知违规输入。把绿色包装成已验证，与隐瞒失败同价；如实标注边界，接收方才能据此决定是否补证。
