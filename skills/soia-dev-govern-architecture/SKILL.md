# soia-dev-govern-architecture

## 客户可读说明

**能做什么：** 解决影响多个组件的架构判断，交付可实施的选择、对给定方案的问题，或实际漂移清单；不是画图工具，也不代替普通代码实现。

**如何使用：** 提供目标问题、架构/代码范围和已批准约束。先判断本次是设计、评审还是漂移核对，只做所需模式；局部修复不重开架构。

## 核心方法

先确认谁拥有状态、谁可以写、谁消费结果，以及哪个来源能证明现状。代码证明“现在怎样”，用户裁决、契约和 ADR 决定“应当怎样”；两者冲突是偏差，不用现状推翻规范。维度与报告用语见[权威模型](references/authority-model.md)。

- **设计方案：** 从最难改回的假设出发，比较真实可行的选择；写清职责、依赖方向、接口与数据流、失败/恢复语义。优先复用现有边界，只有能降低整体复杂度时才加组件；给取舍与可证伪的验证，不为凑数编造替代项。
- **评审给定方案：** 固定目标和版本，沿关键调用、状态写入与失败路径检查。规格符合性与工程代价分开，只报有证据的冲突，不把评审变成重新设计或改代码。
- **核对长期漂移：** 对照有效裁决与当前实现，找重复真源、越权写入、逆向依赖、过期适配和名义退役仍在用的入口；给来源、实际消费者和影响，读不到或跑不了的标未验证。指标与收口见[漂移核对](references/rot-audit.md)。

跨边界变更写清迁移次序、共存窗口、切换条件、回退与退役证据。涉及状态恢复时按真实风险查重试/重复、部分成功、失效 owner、取消与审计，不每次全套。

## 完成边界

判断落到具体边界、证据和下一步验证；只在依赖或时序不易理解时画最小图。复用项目已有 ADR/契约，不默认新建治理目录、状态库、hook、tracker 或固定报告。默认只读、在对话交付；要求形成设计文档时写批准位置。设计建议不是实施、发布或迁移授权。

## 使用边界

### 依赖与安装

无强制技能依赖。单技能 `npx skills add soia-team/soia-open-dev-skills -a <agent> -s soia-dev-govern-architecture`；整域 `claude plugin install soia-dev@soia` 或 `codex plugin add soia-dev@soia`（先接入市场 soia-team/soia-open-skills）；WorkBuddy 见[专家安装说明](https://github.com/soia-team/soia-open-skills/blob/main/docs/install/workbuddy.md)。完整步骤见[官方安装说明](https://github.com/soia-team/soia-open-skills#安装)；命令不构成安装授权。

**私密信息与中间数据：** 只用授权材料，引用脱敏；不需要凭据，不建配置/state/cache。要保存的交付物写批准位置，临时数据放系统临时目录，客户原文不进技能仓库。

**日志与完成回执：** 结论本身是主要交付；附关键依据、实际改动或未改动与未验证部分。

**维护本技能时：** 修改或审计规则前读[规则依据索引](references/rule-rationale.md)；改完做一次真实前向验收（评审一个给定方案或核对一次漂移），核对输出带来源、实际消费者和影响，未读到或跑不了的部分如实标未验证。
