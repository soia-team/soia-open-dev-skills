# 权威模型：谁拥有状态、谁可以写、谁消费结果

本文件是 `soia-dev-govern-architecture` 的权威模型参考：**先声明事实与决策的归属，再谈结构**。设计方案、评审给定方案与核对长期漂移都加载它；SKILL.md 核心方法的「先确认谁拥有状态、谁可以写、谁消费结果，以及哪个来源能证明现状」一条按本文件展开。记录该落成什么形状仍按 SKILL.md 的完成边界处理，本文件只给判断与报告用语。

## 九维正交模型

对每个承重事实与辖区，用最简且够用的模型，逐维声明：

| 维度 | 要声明什么 | 混同后的后果 |
|---|---|---|
| **事实权威**（Fact Authority） | 哪个来源或规则决定被接受的真相 | 写入者或最近的副本被当成真相，对账失去锚点 |
| **决策权威**（Decision Authority） | 谁可以批准或变更一个承重选择 | 实现变动被当成决策，现状推翻规范 |
| **问责 owner**（Accountable Owner） | 对语义、策略、生命周期与升级负责的人或角色 | 「大家都负责」掩盖真实缺陷，升级路径到事故时才被发明 |
| **写入与准入**（Writers and Admission） | 谁可以提议变更、经哪条路径 | 写入被读成所有权或事实权威，权限替换了授权 |
| **数据分区**（Data Partition） | 辖区、边界与传输规则 | 跨辖区的副本被当成同一事实，传输规则静默失守 |
| **副本**（Replica） | 角色、来源、新鲜度与读语义 | 陈旧副本被当权威读，读语义在调用点各自解释 |
| **提交**（Commit） | 接受、排序或版本、可见性与法定人数 | 可见性与次序不确定，重复与重放无法判定 |
| **冲突**（Conflict） | 预防或检测，加收敛规则 | 靠最后写入者胜出，权威在无人裁决时转移 |
| **恢复**（Recovery） | 触发、决策权威、owner、动作、终态不变量与证据 | 恢复路径无主，收敛失败时无人升级 |

九维共存，互不替代：**写入既不授予所有权，也不授予事实权威。**

## 六类记录权威

当一条记录承载或转送承重事实时，先分离六类权威，再谈结构：

| 权威 | 管什么 |
|---|---|
| **记录范围**（Record Scope） | 在已获授权的改动内，哪些记录在范围内 |
| **事实权威**（Fact Authority） | 哪个来源或规则陈述被接受的架构事实 |
| **决策权威**（Decision Authority） | 谁可以批准或变更这些事实 |
| **编辑权威**（Editorial Authority） | 谁可以记录或修订一个已获授权的事实 |
| **格式权威**（Format Authority） | 谁可以改动结构、元数据与命名 |
| **生命周期权威**（Lifecycle Authority） | 谁可以取代、迁移、归档或删除一条记录 |

三条口径：

- **编辑访问不授予决策权。** 能改文件与有权决定事实是两件事；收到「重组文件」一类请求时，先确认它携带的授权范围，再动事实与历史记录。
- **这份清单本身不授予任何编辑权限。** 动作授权来自用户与宿主，本文件只用于判定与报告。
- 仓库声明的来源与决策、生命周期角色在授权迁移关闭前保持有效；过期的来源可以被质疑，取代它需要决策权威。

## 使用口径

- 只声明实际存在的维度，并保持各自独立；缺哪一维就写归属缺口，而不是合成一个「负责人」。
- 分区、副本、法定人数与多写入者准入都不替代权威模型；它们各自回答不同问题。
- 一个产物可以对一件事是投影、同时权威地记录另一件事，逐关系分别声明。
- 改投影走它的来源与再生成路径，而不是直接编辑投影本身。
- 重叠的事实权威要显式解决：指定优先来源、划分辖区或写明裁决规则；把写入者当作可互换只是把冲突推迟到下一次改动。
- 承重 owner 要写清它拥有什么；相邻职责容易混淆时也写清它不拥有什么。取舍写成正向句：当语义 owner 与运行 owner 的职责在同一条改动路径上重叠时，取语义 owner 为决策权威、运行 owner 为事实记录者，并把重叠处写进升级路径。

## 与漂移核对的挂接

核对长期漂移时，先定位事实权威与决策权威，再谈结构。把「谁写入了某个值」与「谁有权决定这个值」分开判定：前者看写入路径与准入证据，后者看裁决、契约与 ADR 证据。两者不一致时先记为漂移，再谈修复动作。

这条顺序与 `soia-dev-govern-architecture/references/rot-audit.md` 的「重复真源或过期权威」「边界或问责偏离」两个指标直接衔接：来源与 owner 先对齐当前改动路径，候选整改才有判据。

## 本仓改造

- **与 SKILL.md 对齐**：代码证明「现在怎样」，用户裁决、契约和 ADR 决定「应当怎样」，两者冲突是偏差。事实权威对应「谁能证明现状」，决策权威对应「哪份裁决仍然有效」。
- **用途限定为判断与报告**：用维度与权威定位偏差、写清 owner 与归属缺口、给出来源、实际消费者与影响；结论落在证据与下一步验证上。
- **默认复用已有记录路径**：优先使用项目已有的 ADR、契约与记录位置；记录结构只在它确实承载承重事实、且格式与生命周期权威明确授权时才新增。维度是判断工具，不预设新的治理目录、状态库或记录模板。

## 来源与承接说明

- **外部概念**：九维正交模型（事实权威、决策权威、问责 owner、写入与准入、数据分区、副本、提交、冲突、恢复）与「写入不授予所有权或事实权威」「分区、副本、法定人数、多写入者准入不替代权威模型」「一个产物可对一事是投影、对另一事是权威，逐关系声明」「改投影走来源与再生成路径」「重叠的事实权威显式解决」承接自 `lencx` 仓 `keel/SKILL.md` 第 3 节（Declare Authority, Writers, And Projections）；「owner 写清拥有什么，相邻职责容易混淆时也写清不拥有什么」承接自同文件第 4 节（Own Boundaries And Target Scope）。本仓把它们接到 SKILL.md 核心方法「谁拥有状态、谁可以写、谁消费结果」，并补上「先定位事实权威与决策权威，再谈结构」的漂移核对入口。
- **外部概念**：六类权威承接自 `lencx` 仓 `keel/references/architecture-records.md` 的 Resolve Authority Before Structure 一节（外部概念：记录范围、事实权威、决策权威、编辑权威、格式权威、生命周期权威；编辑访问不授予决策权；该清单本身不授予编辑权限；仓库声明的来源与角色在授权迁移关闭前保持有效，过期来源可被质疑但须决策权威才能取代）。本仓据此单列一节，并把「重组文件不附带改写事实的授权」写成正向前置确认动作。
- **外部概念**：**真源分叉**（Truth fragmentation）与**权威模型坍缩**（Authority-model collapse）承接自 `lencx` 仓 `keel/references/rule-rationale.md`（外部概念：副本与生成物比它们的源更容易手改，溯源与对账随之逐次衰减；事实权威、所有权、写入准入、分区、副本、提交、冲突与恢复是正交维度，当成互斥类型或强行合成一个 writer/owner 会同时破坏可用性与管辖权）。本仓 `soia-dev-govern-architecture/references/rule-rationale.md` 已以「真源分叉」与「事实权威与决策权威混同」两行记录这两个失效模式，本文件为它们提供展开后的维度与用法。
- **本仓改造**：把维度与权威限定为判定与报告用语，与「不默认新建治理目录、状态库或记录模板」的完成边界一致；「owner 写清不拥有什么」改写为正向取舍句，避免堆叠禁令。
- **实战素材（指令号）**：`owner-directives` 指令 164（主控不生产、生产性动作派执行者、主控只裁决验收记账）是「写入不授予决策权威、决策与记账各有 owner」的一手来源；指令 219②（`supported-agents.yml` dsh 段与取证法矛盾、version 分叉）是「重复事实权威与 owner 缺口要先于结构整改处理」的一手来源，其出处已记录在本技能 `rule-rationale.md` 的对应行。
