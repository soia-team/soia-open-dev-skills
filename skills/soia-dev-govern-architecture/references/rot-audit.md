# 漂移核对：长期健康的指标与收口

本文件是 `soia-dev-govern-architecture` 的漂移核对参考：**先声明审计范围与证据窗口，再按指标读证据，最后按 Closed/Open 收口**。做长期健康核对（而不是设计方案或评审给定方案）时加载；SKILL.md 核心方法的「核对长期漂移」一条按本文件展开，跨边界变更的迁移次序与退役证据仍按 SKILL.md 的对应段处理。

## 内容导航

- 审计路由：先声明，再取证

## 审计路由：先声明，再取证

开工前把五件事写成一行清单，后续每一步取证都回到这份声明：

| 声明项 | 写清什么 |
|---|---|
| 审计范围 | 哪些模块、边界、守卫与声明在范围内 |
| 选中指标 | 从下表选出本次要读的指标；按范围选，不为了凑齐全表而扩范围 |
| 证据窗口 | 观察多长时间、跨多少个交付周期 |
| 例外基线 | 当前计数与趋势口径：与谁比、比什么 |
| 负控证据 | 最近一次守卫确实失败的时间与方式 |

**证据记账完备的判据：范围内每个指标都有落地证据，或显式标记来源不可得，或有理由的排除。** 三者都没有的指标不算读过，收口时按未验证处理。

## 十个漂移指标

滞后症状（事故、重写）到得晚，领先指标只在值回成本时保留。读水平与方向都要结合仓库语境：预期的产品增长会抬高一个健康的计数。

| 指标 | 怎么读 |
|---|---|
| **抑制项计数**（Suppression Count） | lint disable、unchecked cast、跳过测试、基线条目。基线与趋势默认只缩不涨；经授权的上涨写成一次可见决策——决策权威、理由、窄范围、owner、复核触发、移除条件。未经复核的增长即例外堆积。 |
| **负控新鲜度**（Negative-Control Freshness） | 记最近一次植入或已知违例被检出的时间。结论陈旧时先质疑守卫机制本身，哪怕仓库此刻干净。 |
| **观测到的真实违例历史**（Observed Violation History） | 与负控分开记，作为边界承受的压力。长期安静本身不构成退役一个可证伪守卫的理由。 |
| **公开表面增长**（Public Surface Growth） | 按周期比较导出、字段与选项的增量与交付的行为或结果。表面增速超过交付，说明承诺可能被当作副作用铸造出来。 |
| **概念计数**（Concept Count） | 数新增名词——service、manager、layer、配置键——并与退役概念或显式接受的净增长对照。 |
| **重复真源或过期权威**（Duplicate Truth or Stale Authority） | 查同一事实能否经多条路径独立编辑，以及声明的来源或 owner 是否还匹配当前的改动路径。有意的联邦与副本在维度与对账显式时不算缺陷。 |
| **边界或问责偏离**（Boundary or Accountability Divergence） | 代码扩大或穿越声明边界时，查契约与决策权证据是否同步。契约未变时的内部改动不算漂移。 |
| **绕过频率**（Bypass Frequency） | 记受治理路径被跳过的频次。排除控制策略后仍上升，先看可避免的路线成本；判定对象是路径，而不是个人。 |
| **未声明的跨边界 import**（Undeclared Cross-Boundary Imports） | 数违反声明依赖方向或绕过公开面的 import。按声明边界判，不按目录亲缘判。 |
| **手工编辑的派生文件**（Hand-Edited Derived Files） | diff 触及声明的生成物，说明生成器比直接编辑更贵。先改进生成路径，再谈把手工编辑规范化。 |

## 证据记账与保留

- **优先复用已有的证据**：版本历史、既有检查产物与已有度量足以支撑多数指标，本仓不新建第二真源。
- **确需新快照时声明五件事**：范围、节奏、保留期、owner、删除条件。
- 每个在用指标声明自己的范围、证据窗口与已知盲区；不为测量漂移而无界追加历史。

## 收口契约：Closed 与 Open

按 Closed/Open 两态收口，口径见 `soia-dev-implement-task/references/acceptance-line.md`。不可得来源或排除项若可能改变承重决策，就贡献 applicable findings 或 decision-changing unknown，并据此选 Open。

两种状态都要额外给出四件事：

| 交付项 | 内容 |
|---|---|
| 不行动或减法候选 | 至少一条有理由的「维持现状」或「减掉一处」候选；治理的结论可以是减法 |
| 指标 owner | 每个指标一个 owner，或明确指出归属缺口 |
| 下次复核触发 | 触发条件，优先复用项目已有的复核触发条件 |
| 下一次快照 | 若有，附范围、节奏、保留期、owner 与删除条件 |

## 判据

1. **指标是健康的投影，不是健康本身。** 数值转好可以来自范围收窄或检测器失明；每条结论回到它的范围、窗口与盲区。
2. **安静信号先验证，再当作健康证明或退役依据。** 沉默可能是规则有效、路径休眠或检测器失明；退役一条守卫需要更简义务保护同一不变量，或有证据表明该机制不再影响决策。
3. **复用项目已有的复核触发条件。** 没有时，一个令人担忧的趋势先成为 owner 的 finding，而不是自动工作项。
