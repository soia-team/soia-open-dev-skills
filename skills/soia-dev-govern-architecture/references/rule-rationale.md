# 规则依据索引：架构治理

`soia-dev-govern-architecture` 的 SKILL.md 陈述规则；本文件记录规则承载不了的部分：**每条失效模式为什么反复发生，以及它被哪条规则挡住**。这是维护索引，不是「一条规则配一个测试」的要求：只在某行能解释一个非显然的设计选择时保留它，重叠的机制优先合并，而不是再加一条规则。

使用口径：观测到的沉默是弱证据——某条规则可能有效、该路径可能休眠、检测器可能失明。退役一条规则的理由是**出现了保护同一不变量的更简义务**，或**有证据表明该机制不再影响决策**；仅仅没再出现，两者都不成立。

## 失效模式 → 机制 → 规则

| 失效模式 | 机制（为什么反复发生） | 规则 |
|---|---|---|
| **真源分叉** | 副本与生成物比它们的源更容易手改，于是溯源与对账逐次衰减；同一份可变列表在两处各自维护，两边都看起来是权威 | 核对长期漂移；完成边界（复用已有真源） |
| **投影与权威混淆** | 把某类文件（缓存、记录、视图）一律当作非权威，会同时掩盖它合法拥有的运维事实，和它真正只是投影的那些事实 | 核心方法（代码证明现在怎样，裁决决定应当怎样） |
| **现状推翻规范** | 实现是随手可读的，「应当怎样」需要先找到有效裁决；两者冲突时现状更容易被当成答案 | 核心方法（冲突是偏差） |
| **事实权威与决策权威混同** | 谁写入了某个值，与谁有权决定这个值，是两个正交维度；合成一个「负责人」会同时破坏可用性与管辖权 | 核心方法（谁拥有状态、谁可以写、谁消费结果） |
| **责任真空** | 决策权、分区、平局裁定或生命周期责任缺位时，问责静默衰减；「大家都负责」与「指定的唯一负责人」都能掩盖真实缺陷 | 设计方案（职责）；完成边界 |
| **横向耦合** | 伸手进另一个域的内部只是一条 import；协商一个声明过的公共面是一次设计对话。选择偏向 import | 设计方案（依赖方向；优先复用现有边界） |
| **共享层倾倒** | 把域语义移进通用下层能立刻让 import 图变干净，代价是把共享层变成永久的协调税 | 设计方案（只有能降低整体复杂度时才增加组件） |
| **偶然稳定** | 导出只要一次按键，它产生的承诺在有人因变更被破坏之前是不可见的 | 跨边界变更（兼容承诺、切换条件） |
| **承重事故** | 消费者足够多时，每一条可观察行为都会被依赖，无论作者是否有意（Hyrum 定律）。写下的契约永远是实际交付契约的子集 | 跨边界变更（退役证据）；核对长期漂移 |
| **约束型架构** | 风险与缺失事实比一个连贯的目标方向更容易枚举；第一个看起来可行的接缝也容易在真正比较之前就成为在位者 | 设计方案（从最难改回的假设出发） |
| **快乐路径架构** | 演示与精美报告奖励过早收口；一个具名的恢复路径或自信结论可以掩盖缺失的授权、归属与终止不变量 | 设计方案（失败/恢复语义）；核对长期漂移 |
| **时间轴泄漏** | 组件在单进程单次运行的夹具里被测；重启、重试、重放、提交不确定与收敛失败只存在于生产 | 设计方案（失败/恢复语义）；跨边界变更（共存窗口、回退） |
| **迁移只写目标不写次序** | 声明一个干净的目标态比写清次序便宜，而次序恰恰是消费者、数据与旧路由最容易被漏掉的地方 | 跨边界变更（迁移次序、共存窗口、切换条件、回退、退役证据） |
| **名义退役** | 标记退役不消耗任何运行时资源，删掉最后一条调用路径才消耗 | 核对长期漂移（名义退役但仍在使用的入口） |
| **纸面边界** | 无主的纯散文规则容易被绕过和遗忘；实质规则需要相称的可证伪执行，未上自动化时审查机制与其证据仍需显式且可审计 | 完成边界 |
| **墙上守卫** | 从不触发的守卫与一个正常工作的守卫，在有人植入违规之前无法区分；吵的守卫被关掉，安静的守卫被信任，两者都归于零保护 | 完成边界 |
| **异常累积** | 每条例外单独看都合理，列表只增不减，因为移除既没有归属也没有期限 | 核对长期漂移 |
| **架构仪礼膨胀** | 把私有或可逆范围当作非架构会丢掉真实的模块选择；对这类选择套用全部关切，会让治理比绕过它更贵 | 完成边界（按真实风险选择，不每次全套检查） |
| **重写引力** | 一旦理解成本超过重写成本，重写对个人就显得局部理性；它摧毁的制度知识从来不记在那个人的账上 | 核对长期漂移（先定位真实漂移再谈替换） |
| **概念通胀** | 命名一个新事物是作者的乐趣、读者的税；这笔税在引入它的那次改动里不可见 | 完成边界（不默认新建治理目录或状态库） |
| **知识蒸发** | 理由活在脑子里和聊天记录里，规则活在文件里；规则比理由活得久，随后不是变成迷信就是变成噪声 | 完成边界；核对长期漂移 |
| **历史语境被伪装成当前事实** | 历史记录保留旧路径是正确语境；把未实现的描述读成当前状态，只在有人跨文件复核时才暴露 | 核对长期漂移（给出来源、实际消费者与影响；未验证标未验证） |
| **平台能力假设** | 工具能力在文档里看起来完备，实际接口可能没有该动作；把「做不到」写成「已完成」比承认边界便宜 | 完成边界（未读到或无法运行的部分标为未验证） |

## 来源与承接说明

- **外部概念**：「失效模式 → 机制 → 规则」三列索引形态、以及「观测到的沉默是弱证据」「退役理由须是更简义务或机制不再影响决策」两条维护口径，承接自 `lencx` 仓 `keel/references/rule-rationale.md`（39 行表）。通用模式中 **真源分叉**、**投影与权威混淆**、**事实权威与决策权威混同**、**横向耦合**、**共享层倾倒**、**偶然稳定**、**承重事故**、**快乐路径架构**、**时间轴泄漏**、**纸面边界**、**墙上守卫**、**异常累积**、**架构仪礼膨胀**、**重写引力**、**概念通胀**、**知识蒸发** 源自该表（外部概念，本仓改写并入本技能规则名）；**责任真空** 与 **约束型架构** 亦源自该表，并结合本仓 `execution-policy` 的职责分层表述。
- **实战素材（指令号）**：**真源分叉** 与 **责任真空** 取自 `owner-directives` 指令 219②（`supported-agents.yml` dsh 段 `model_integrity` 与取证法矛盾、version 分叉、SKILL.md `updated_by` 旧表述，立「dispatch 技能残余批」修复）；**历史语境被伪装成当前事实** 取自指令 190（板与实现四处冲突，板内 zh/en 说明同步改写，**板原有的「不要竖条」理由完整保留在注释里**并记录它为何不再成立）与指令 192（两个一代手绘画布原样保留并在台账写明理由）；**平台能力假设** 取自指令 192（Artifact 工具无 delete 动作，真正删除需 Owner 自行操作——边界如实写出而非包装为已完成）；**迁移只写目标不写次序** 取自指令 193（worktree 错基线停在 `d6c5496b`，预检抓到后重置 `master`）。
- **实战素材（本仓一手）**：**纸面边界** 与 **墙上守卫** 的负控口径与 `soia-dev-enforce-coding-protocol` 的「先找证伪办法」同源，本仓在指令 193 有过一次实证（`check_docs.py` 并入 `check_goal_graph.py` 后做负向测试，确认退出码 1 且错误指名版本差）。
