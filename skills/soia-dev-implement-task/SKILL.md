# soia-dev-implement-task

## 客户可读说明

**能做什么：** 把一个工程需求、缺陷或 finding 做到可验证的完成，覆盖代码、配置及其行为契约文档。README 拼写或契约不变的纯文字修正不走本流程；“只诊断”不变成改代码。

**如何使用：** 提供目标、所在项目和已知约束。信息够就推进；只有会改变结果、权限或安全的歧义才暂停对应动作。

## 实施

1. **最小工作边界。** 以目标项目规则、相关实现与直接调用方为界，保留现有改动；复用项目已有任务记录，局部修改不另建治理系统。
2. **沿一条可验证行为推进。** 先写或选一个具体验收例；适合自动化时走 测试失败 → 最小实现 → 测试通过，再做必要整理。不先批量写完所有测试或改完整个模块。
3. **缺陷先定位。** 从输入、日志或失败测试复现，沿数据与调用路径找到首个偏离点，验证一个具体假设再改。复现路径不清时按[诊断回路](references/diagnosis-loop.md)先建一条能在本缺陷上变红的回路。只要求诊断时，交原因、证据与修复建议后停。
4. **Findings 逐条决策。** 按当前候选核实，标 fix / reject / defer 并给理由；只修已授权且成立的项，不靠编号清零冒充完成。
5. **验证并收口。** 跑最靠近改动的检查，核对真实结果与最终 diff；高风险边界补直接消费者和失败路径。失败只推进相关修复，有新证据才扩大验证；无进展就停下报告还缺什么。
6. **评审按本次政策。** 用户或项目要求独立评审时，自检后发起一次并随交付回报；否则低风险局部修改自核即可，不因调用本技能自动加评审或 panel，也不递归派发。审核者只读固定候选，收到目标、范围、验收标准与实现者模型证据，不被预设结论或排除范围内问题。同宿主用内置 subagent，外部 CLI 才加载 `soia-dev-agent-cli-dispatch`。独立性按用户/项目政策，至少排除同一实际模型自审，无政策时用不同模型家族；模型证据缺失标未验证，不用请求值代填；额度、费用或权限不满足时报告评审未执行，不静默换模型。评审交的是判断，不是合并许可；主控核验关键证据，冲突项并列交裁决。

用户或项目要求正式验收线时，按[验收线](references/acceptance-line.md)给逐项证据与 Open 回执；普通局部修改对照约定行为和实际检查收口，新增守卫或修复失败路径时仍要证明检查能识别错误。**仅修改 AI Provider 适配时**读 [AI Provider 验收](references/ai-provider.md)，不把消息、工具或计费检查套到所有 adapter。

## 交付与边界

- 沿用已批准架构和样式；遇到跨组件契约或不可逆迁移决策，先说明需要确认的选择，局部实现不重开架构设计。
- 不吞错、不削弱断言、不静默降级来变绿；保留历史失败，分清本次通过与未覆盖的全局问题。
- 已有授权不逐步重问；没有新候选或新证据不循环审查。提交、合并、发布、部署、安装或扩大修复范围不因“实现完成”自动获得授权。
- **日志与完成回执：** 结果在前，附关键改动、真实检查与残余风险；要求的评审给结论或未执行原因（独立性缺证据标 `blocked_independence`），冲突项两方说法并列；finding 输入另列 fix/reject/defer。没跑的检查直说未验证。

### 依赖与安装

无强依赖，用目标项目已有工具，不自动安装。单技能 `npx skills add soia-team/soia-open-dev-skills -a <agent> -s soia-dev-implement-task`；整域 `claude plugin install soia-dev@soia` 或 `codex plugin add soia-dev@soia`（先接入市场 soia-team/soia-open-skills）；WorkBuddy 见[专家安装说明](https://github.com/soia-team/soia-open-skills/blob/main/docs/install/workbuddy.md)。完整步骤见[官方安装说明](https://github.com/soia-team/soia-open-skills#安装)；命令不构成安装授权。

**私密信息与中间数据：** 最小范围读写，保留他人改动；秘密不进源码、日志或回执。临时复现用系统临时目录，客户交付物写确认的路径。
