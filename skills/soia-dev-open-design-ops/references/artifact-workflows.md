# HTML 原型、deck 与动画

承接原 design-explorer 的工具交付能力；不是把 HTML deck 改成 PPTX 的格式替换。选择客户所需产物，只检查相关条目，不固定方向数或报告模板。

## 输入与运行

确认用途/受众、主产物、目标画幅、真实内容、品牌资产与可接受占位。输入足以形成初版就继续，缺少会改变结果的素材才问。

按 SKILL.md 识别 Open Design 路线，并遵守用户/宿主选定的 provider。优先复用正确项目与 conversation；参考相同产品已正确应用设计系统的页面，或把本轮必要的 token/组件约束内联到 brief，让实际执行者可读。不要假设它能访问未挂载的设计系统目录。

MCP/CLI 的调用参数来自当前 schema/help。brief 写明输出目录、文件、非目标和不得覆盖的原件；完成后核对实际目录树与触及文件，不能只信 brief 被遵守。原生 run 必须等实际结果；超时、不支持或环境缺失如实报告，不悄悄换生成路线。

## 产物与验收

| 产物 | 交付 | 实际检查 |
|---|---|---|
| 原型 | HTML 与必要本地资源、可点击关键流程 | 页面真实渲染，主要动作/返回路径可用；静态部分明示 |
| HTML deck | 幻灯片 HTML、资源与相关 presenter/导航能力 | 逐页检查内容/页数/画幅/溢出，前后导航和演示状态；不是一张长网页截图 |
| 动画 | 可运行 HTML composition、资源；要求视频时另交实际导出文件 | 起止/中间时刻与时长，播放/暂停或项目约定控制；验证 MP4/GIF 的真实编码与可播放性 |
| 风格探索 | 少量有实质差别的可见方案 | 同一内容/画幅可比较，品牌证据或占位明确；不擅自替换正式稿 |

选择 deck template 前查询真实模板目录，不把 functional skills 当渲染模板。参考操作说明中的 simple-deck、guizang-ppt、html-ppt 仅作为历史示例，当前是否存在由实际目录确认。

PPTX 是附加导出：截图式仅承诺保真，不承诺可编辑；要求可编辑时使用实际支持的生成链，并核对文本/形状与源 HTML 的一致性。视频使用真实支持的 renderer/composition 契约；没有导出能力时保留可运行 HTML 并明确未完成视频，不把预览冒充成片。

## 保存与边界

临时预览用 OS 临时目录；客户要保留的源文件与导出写指定交付位置，不自动发布、归档到代码仓或写远端。保存/覆盖前核对目标现状和授权，不清理原始项目、客户配置或历史证据。

最终给可用产物及验证缺口。工具生成验证不等于 UI 审查、生产接入或桌面客户端交互通过。
