# soia-dev-review-code

## 客户可读说明

**能做什么：** 判断给定改动是否满足请求、是否引入具体风险。只读：不修复、不提交、不评论到远端、不合并。

**如何使用：** 提供 diff/PR/技能目录及目标。候选 SHA 或快照、范围与项目规则能从现有材料取得就自己取，不向用户重复索要；取不到必要材料时说明缺口，不猜版本，不声称已审。

## 一次审查

1. **规格符合性。** 对照请求、已批准设计和验收行为读实际实现，找漏做、做错或越界。已有架构是约束，不借审查另选一套。
2. **工程标准。** 沿直接调用边界查正确性、输入安全、错误处理、兼容性和测试断言；只扩展与本次风险相关的视角。
3. **核实候选问题。** 回到原文与调用上下文确认触发条件、反例和实际影响；可安全运行的聚焦检查可以跑，外部副作用不作审查手段。确认不了的放未验证项，不包装成缺陷。
4. **交付后停。** 只报会改变下一步动作的问题，按严重度给位置、触发条件、影响与依据。没有新 diff、新证据或明确要求不循环复审。

默认一次审查。独立评审由一个符合用户/项目独立性政策的审核者完成，不等于双评估或 panel；同一实际模型换会话不能冒称异模型独立审查。明确要求多视角/panel 时才读[多视角审查](references/independent-review.md)。同宿主用内置 subagent，外部 CLI 才用 dispatch 技能。

## 什么算验过

上面判「改得对不对」；「验没验过」按下列取证，不凭记忆：

1. **门清单以项目 CI 配置为准。** 取本次改动路径（`git diff --name-only <基线>...HEAD` 加未跟踪文件），从项目 CI 配置逐条读出门，不从上一单回执抄。项目有按改动路径解析 CI 配置、规则路由表与验证指南的影响面脚本时直接用（例如输出「适用真源 / 必跑门 / 适用技能」三段的清单脚本）；它只路由不判定，退出码不是验收结论。
2. **领域检查是补充。** 项目验证指南按改动面点名的检查逐条对表，命中的全跑；它加在 CI 门之外，不用来缩减 CI 门。
3. **先量基线再对拍。** 基线已有红项时，证明的是「没让红变多」：同一环境逐条给本次 EC 与基线 EC，不把既有红算到本次头上，也不拿「基线本来就红」豁免新增的红。
4. **退出码取被测命令自己的。** 用 `cmd >file 2>&1; echo $?`；`cmd | tail` 后的 `$?` 是 tail 的，会把红报成绿。没跑的门写「未运行」，不用静态检查、历史证据或 `skipped` 冒充。
5. **跑门不破只读。** 只跑无副作用的检查；`--check` 类生成器不改成 `--write`，不改工作树、产物或被审候选，需要缓存或数据根时用临时目录。

回执写清跑了哪些门、各自 EC、与基线的对拍、没跑的及原因。门全绿不等于建议通过，门有红也不等于本次改动有错，结论仍按「一次审查」给。

## 被派发时的入口

已按政策获准的一次独立评审用这个入口；收到评审任务不再往下派评审。

- **输入**：候选标识（commit SHA / 快照摘要或内容指纹）、任务书或验收标准、改动范围、实现者模型标识（Independence Gate 的 `executor_model`）。固定不了候选就说明缺口，不审会漂移的版本。缺实现者模型标识时独立性记 `blocked_independence`，不写「已独立复核」；仍可交付对固定候选可证实的内容审查，但不能据此放行要求独立性的门禁。
- **输出**：声明实际审核者、模型证据和审查形态，再给建议、可核实问题与未验证项。只有原本要求 panel 而未完成时标缺失侧，不把格式缺项当代码缺陷。
- **全程只读**：审查前后核对候选未变，变了就把结论限定到已审版本。
- **结论不是放行**：放行由主控验收决定，自动调用不带来修复权或提交权。

## 技能包分支

审技能时读其正文和受影响资源，核对命令/接口、授权门、跨宿主可用性、元数据与依赖一致性。行为变化要看自检和真实输入的前向测试证据；目录存在或静态校验通过不等于有效。命令核实用无副作用方式或官方文档，不靠运行发布、发送或安装来“验证”。

## 结果与边界

**日志与完成回执：** 先给建议（建议通过 / 建议先改 / 建议拒绝），再列可行动问题与覆盖/未验证范围。无问题可写“未发现可确认问题”，不保证没有缺陷；结论不是合并许可。

### 依赖与安装

无强依赖，用目标项目已有工具，不自动安装。单技能 `npx skills add soia-team/soia-open-dev-skills -a <agent> -s soia-dev-review-code`；整域 `claude plugin install soia-dev@soia` 或 `codex plugin add soia-dev@soia`（先接入市场 soia-team/soia-open-skills）；WorkBuddy 见[专家安装说明](https://github.com/soia-team/soia-open-skills/blob/main/docs/install/workbuddy.md)。完整步骤见[官方安装说明](https://github.com/soia-team/soia-open-skills#安装)；命令不构成安装授权。

**私密信息与中间数据：** 只读约定范围，不展示秘密或无关源码；可能生成缓存的检查用临时目录，不改源码、规范、测试或工作树状态。
