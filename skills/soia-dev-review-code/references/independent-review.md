# 独立审查：双评估隔离、降级可见与门禁挂钩

本文件是 `soia-dev-review-code` 的独立审查执行形态参考，把 SKILL.md「一次审查」末段那句「默认单次审查；只有用户或项目明确要求时使用独立多视角/panel。自查不能冒称独立审查，换一句角色宣言也不是独立证据」展开为可执行形态。

默认档不需要加载本文件：单次审查直接按 SKILL.md「一次审查」四步走。用户或项目明确要求独立审查、多视角或 panel 时加载本文件，此时 SKILL.md 第 1 步（规格符合性）与第 2 步（工程标准）合入评估 A，第 3 步（核实候选问题）的机械部分落入评估 B，第 4 步（交付后停止）与末段口径约束综合与报告。

## 内容导航

- 默认值与升级：单次是默认档
- 评估 A：判断侧
- 评估 B：机械证据侧
- 隔离与次序：A 先于 B 的机械输出
- 报告首行：`Method:` 溯源与 DEGRADED 横幅
- 与 Independence Gate 的挂钩
- 综合与边界：拧成一份结论，交付判断而非许可

## 默认值与升级

本技能默认**单次审查**：默认不启用多视角、panel 或多执行体，默认形态就是 SKILL.md 的「一次审查」四步，本文件的双评估形态在默认档不生效。

只有用户或项目明确要求时才升级到独立审查：请求里出现「独立审查」「多视角」「panel」「第二个执行体」这类明确要求，或项目规则把本次改动定为需要独立复核的风险档。升级是一次显式决定，理由是「这次改动值得一份不共享上下文的判断」；请求里没有这层要求时，默认档的四步就是完整交付。

升级后由两份评估共同构成一次审查：A 出判断，B 出机械证据，二者在综合步合流。缺任何一侧都按下方「报告首行」挂降级横幅。

## 评估 A：判断侧

评估 A 回答「这份实现是否满足规格、是否够工程标准」，独立形成自己的疑点与结论：

- **规格符合性**：对照请求、已批准设计与验收行为读实现，找漏做、做错与越界；已有架构是约束，不借审查另选一套。
- **工程标准**：沿直接调用边界检查正确性、输入安全、错误处理、兼容性与测试断言，只扩展与本次风险有关的视角。
- **自己的疑点**：在看不到 B 输出的前提下写下自己怀疑什么、依据是什么、还需要什么证据才能定论；这份疑点清单在综合步与 B 的机械输出逐条对照。

读法沿直接调用边界展开：先读被审实现本身，再读调用方与直接依赖，形成可定位的问题候选。结论用与 SKILL.md 相同的口径表达——位置、触发条件、影响与依据。

## 评估 B：机械证据侧

评估 B 回答「在固定候选上，机器能观察到什么」，在一份冻结的候选上收集可复现证据：

- **固定候选**：先记下被审版本标识（commit、快照摘要或内容指纹），B 的全部命令跑在同一份候选上。
- **聚焦检查**：静态分析、最窄相关测试、内容校验、lint 或类型检查，取目标仓已有工具，按本次风险选最相关的一项或几项。
- **命令与真实输出**：B 的产物是命令加上它的真实输出，退出码与关键输出片段一并记录，失败与超时同样记录。
- **误报标注**：每条机械发现标注能否复现；疑似误报留给综合步裁定。

B 只读取与运行，不改工作树：需要生成缓存的检查用临时目录，需要外部副作用的检查换无副作用方式或官方文档核实。

## 隔离与次序：A 先于 B 的机械输出

两份评估在上下文上互不可见，各自只拿到任务书、候选标识与自己的输出契约：

- **互不可见**：A 看不到 B 的命令与输出，B 看不到 A 的疑点与结论；两侧各自新建执行体或上下文，不共享对话历史。
- **次序**：**A 必须在 B 的机械输出进入综合上下文之前完成。** 机械输出是确定性的，但它仍然会锚定判断——先读到「检测器报了 7 条」再读实现，A 的注意力会围着这 7 条转，独立判断随之失效。
- **并行形态**：有子代理或独立进程能力时，两个评估并行派发、各自新建上下文；B 可以在自己的上下文里先跑完并把输出暂存，A 完成之后才让它进入综合。
- **退化形态**：没有子代理或独立进程能力时，才退化为单上下文顺序执行：跑完并记录 A，再跑 B，最后综合，并按下方横幅标注降级。

## 报告首行：`Method:` 溯源与 DEGRADED 横幅

报告第一行声明本次实际执行形态，二选一：

| 本次形态 | 报告第一行 |
|---|---|
| 双执行体 | `Method: dual-agent (A: <执行体标识> · B: <执行体标识>)` |
| 降级 | `⚠️ DEGRADED: single-context (<原因>)` |

标识用可核对的执行体或模型标识（例如执行器与模型名），**「审查员」「独立评审」这类角色宣言不算标识**，写进 `Method:` 也不构成独立证据。

任何形式的降级都挂横幅，覆盖这四种来源：无子代理或独立进程能力、用户拒绝派发、派生失败、只跑了一侧。原因写具体事实，例如 `(sub-agent unavailable in this session)`、`(spawn failed: <exact error>)`、`(assessment B failed, judgment side only)`。

降级不是失败结论：单上下文顺序执行照样能产出可用的问题清单。**静默降级才等于这次审查失败**——报告读者有权知道这份判断产自哪个形态，横幅就是那行可见的凭据。

## 与 Independence Gate 的挂钩

本文件管审查侧的执行形态；独立性资格由 `soia-dev-agent-cli-dispatch/references/dispatch-contract.md` 的 Independence Gate 机械判定，本文件不另立一套独立性定义。

需要外部执行体时按该技能的调用契约派发，`dispatch_role=reviewer` 触发门禁：

1. 派发必须提供被审实现者所用模型 `executor_model`；缺少对照对象时判 `blocked_independence`，调用不发生。
2. 门禁比较 catalog 中两模型的 `provider` 与 `model_family`：同 provider 且同 `model_family` 判 `blocked_independence`，调用不发生。
3. 被审模型（对照模型）不在 catalog 中时同样阻断：无法比对家族就不能宣称独立，先登记该模型。
4. 审查模型不在 catalog 时不阻断，但独立性只能标 `unverified`，报告写「独立性未验证」；「已独立复核」只在门禁放行且执行体标识可核对时出现。
5. 跨代同厂在 catalog 中是不同 `model_family`，门禁放行；是否足够独立由派发者按任务风险判断，门禁不替你下这个结论。

机械判定走 `soia-dev-agent-cli-dispatch` 的 `scripts/route_model.py --role reviewer --executor-model <被审模型>`，完整参数、状态枚举与回执字段见 `soia-dev-agent-cli-dispatch/references/dispatch-contract.md`。门禁判 `blocked_independence` 时本次独立审查不成立，报告如实写出门禁结论与它挡下的调用，写成「未执行」而不是「已审、未发现问题」。

## 综合与边界

综合不是拼接：两份评估的输出拧成一份报告，逐条处理三类关系。

| 关系 | 处理 |
|---|---|
| 两侧一致 | 结论互相加固，合并为一条问题，依据同时引用判断与机械证据 |
| B 抓到而 A 漏掉 | 作为独立发现列出，注明来自机械证据并附复现命令 |
| B 的误报 | 在综合步明确驳回并写驳回理由，不进问题清单 |

每条问题仍按 SKILL.md 的口径交付：位置、触发条件、影响与依据；按严重度排序，只报告会改变下一步动作的问题。A 的疑点清单在综合步逐条落定——能定论的进问题清单，未定论的进未验证项。

边界三条：

- **只读**：审查全程只读候选，工作树状态在审查前后核对一致；候选发生变化时把结论限定到已审版本。
- **判断而非许可**：独立审查的产物是判断与问题清单，不是合并许可。结论用 SKILL.md 的「建议通过 / 建议先改 / 建议拒绝」表达，通过建议不等于批准合并；发现问题时交付问题清单，修复、提交与远端评论各自走独立的授权动作。
- **自报是输入**：A 与 B 的「完成」回报都按证据复核后才进入综合，没有可核对证据的结论标未验证。

## 来源与承接说明

- **外部概念**：双评估分工、两评估互不可见、A 先于 B 的机械输出进入综合、`Method:` 首行溯源、`⚠️ DEGRADED: single-context (<原因>)` 横幅、综合需写出「一致 / 机械侧多抓 / 机械侧误报」三类关系，承接自 `pbakaus/impeccable` 仓 `skill/reference/critique.md`（外部概念），该仓对应的 agent 文件 `agents/impeccable-finish-reviewer.md`（外部概念）提供同一路「只读、无浏览器、把证据检查与处置词分离」的评审器形态。
- **本仓改造**：外部仓默认双评估，本仓刻意保留「**默认单次审查**」这个默认值——单次是本技能客户可读说明里的承诺形态，升级只在用户或项目明确要求时发生，因此本文件是升级档而非默认档。外部仓的浏览器检测器、快照持久化与 heuristic 评分不承接，本仓的机械证据侧取目标仓已有的最窄检查。独立性资格挂接 `soia-dev-agent-cli-dispatch/references/dispatch-contract.md` 的 Independence Gate：外部仓没有这层门禁，本仓把「审的人与做的人是否同血统」交给门禁机械判定，本文件负责把判定结果与执行体标识写进报告首行。
- **实战素材（指令号）**：`owner-directives` 指令 164（主控不生产、生产性动作派执行者、主控只裁决验收记账）是「独立审查另派执行体、主控在综合步裁决」的一手来源；指令 222（图状态回写必须逐条附一手证据，对账批不得凭表述补 passed）是「执行体自报完成只是待验证输入」与「降级必须可见、静默降级等于审查失败」的一手来源。
