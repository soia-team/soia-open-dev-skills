# 表达参考

仅在结构、运行过程或改动不容易用一个简单视图说清时读取，按当前问题选用。

## 结构与运行分开

目录树说明文件职责；组件树说明界面组成和状态归属；调用树说明真实执行顺序。不要把文件包含关系画成函数调用。

```text
订单页 [拥有筛选状态]
  筛选栏 [接收条件，发出变更]
  订单列表 [展示结果]
```

需要解释请求如何跨模块完成时，再沿实际实现列调用链；异步返回、重试或多个参与者的顺序重要时用时序图。只保留影响当前结论的参与者和边界。

## 对比与目标形态

用户关心“哪里变了”时，在既有结构上展示关键增删；用户需要新结构的完整形态时，展示完整相关片段。不要为了少几行而藏掉状态由谁持有、动作先后或必要上下文。

例如取消操作新增前置检查时，聚焦控制流变化，不顺带展示整个服务：

```diff
 cancel(order)
+  verify_owner(order)
+  require_unshipped(order)
   request_refund_once(order)
```

## 转为 HTML 的条件

只有空间布局、状态并排对比或信息密度确实超出文本图表达能力时才写 HTML。用真实标签与已核实内容，沿用产品视觉；一页围绕一个理解目标，可包含多个必要视图，不扩成通用仪表盘。

示例仅说明表达方式，不是业务规则或已验证调用链；实际展示必须来自当前任务材料。
